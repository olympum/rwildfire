# Contributing

Start from a bounded issue in this repository. Full parity is the target, while each pull request must state which behavior its evidence covers.

## Reference discipline

Read the [parity evidence decision](docs/adr/0001-parity-evidence.md). Use real outputs from the pinned Java implementation rather than expected results generated by the Rust code being tested. Keep source checkouts, compiled classes, toolchains, and transient captures out of Git.

Reference regeneration is an explicit, reviewable change. Record the upstream revision, probe revision, suite/seed, toolchain identity, and reason for the update. Never repair a failed comparison by silently replacing the golden.

## Validation and review

Run `./scripts/check` before pushing a code change and record its observed result in the pull request. The hosted check runs the same gate. Missing Java, an empty suite, or a skipped probe is not a pass. The initial gate targets Linux; other platforms need their own observed evidence before support is claimed.

Every test must protect observable behavior or an independent contract and name a credible regression. Prove that a load-bearing check rejects a deliberate violation, and confirm the intended tests actually executed. Independent peer review is required before merging material changes to the harness or port.

Keep acceptance failures open until corrected and proven. Link incomplete compatibility work to its programme issue instead of describing an unsupported feature as equivalent.

## Scope and licensing

Do not introduce renderer features before the harness milestone is accepted. New source and assets must have documented provenance and compatible terms. Original rwildfire code is GPL-3.0-or-later; upstream and third-party materials retain their own licenses. See [source attribution and distribution scope](NOTICE.md).
